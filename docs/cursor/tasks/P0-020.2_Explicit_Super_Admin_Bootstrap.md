# P0-020.2 — Explicit Super Admin Bootstrap

Fix the Super Admin role implementation. Focus only on authorization, bootstrap, redirects and tests. Do not redesign the dashboard yet.

## Current defect

`python -m app.cli create-super-admin` creates:

`role = "admin"`

It must create:

`role = "super_admin"`

The current development database contains one disposable administrator account and no real data. Do not modify/delete it during this coding task; the user will reset and recreate it after verification.

## Requirements

### Backend role hierarchy

Implement explicit roles:

`super_admin > admin > faculty > student`

- Add `super_admin` to internal role constants and schemas where appropriate.
- `super_admin` inherits all permissions granted to `admin`.
- Add a dedicated `require_super_admin` dependency for Super Admin-only operations.
- Existing `require_roles("admin")`, `is_admin()` and equivalent authorization helpers must accept both `admin` and `super_admin`.
- Do not automatically give ordinary admins Super Admin-only permissions.
- Public registration and administrator provisioning must reject both `admin` and `super_admin`.
- Student/faculty activation can never assign either role.
- `/auth/me` must return `super_admin` accurately.
- Inactive/deactivated Super Admin accounts remain unauthorized.

### Bootstrap command

Correct:

`python -m app.cli create-super-admin`

It must:

- Create exactly `role="super_admin"`.
- Refuse when any Super Admin already exists.
- Also refuse unsafe duplicate email/mobile identifiers.
- Prompt interactively; no password in arguments or logs.
- Apply existing password, email and mobile normalization.
- Create an active/activated account.
- Never create an ordinary admin.
- Preserve the existing no-default-credentials rule.

### Frontend authentication

- Treat `super_admin` as an authorized administrator.
- Redirect both `super_admin` and `admin` to `/admin-dashboard`.
- Display `Super Admin` for `super_admin`.
- Display `Administrator` for `admin`.
- Do not infer the label from the route.
- Registration UI must never expose administrator roles.

### Database

- If the role column has an enum/check constraint, add a follow-up Alembic migration.
- Do not edit deployed data automatically.
- Preserve P0-020 and P0-020.1 identifier constraints.
